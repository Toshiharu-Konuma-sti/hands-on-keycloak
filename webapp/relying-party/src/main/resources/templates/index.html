  • 目的：スコープ（RP（アプリ）に許した操作）と、ロール（ユーザーに与えられた役割）が、RS（Web API）の実行結果にどう関わるかを体験する
  • 題材：「経費精算」（※ データは動作確認用のダミーであり、実際の業務管理は行わない）
  • 操作：アプリ（経費申請アプリ／経費承認アプリ）と、ユーザー（一般社員／課長／部長）を切り替えて、APIの実行結果を確認する
  • 見るところ：APIはスコープとロールを用いて実行許可を判断するため、成否（200 / 403）と拒否理由の実行結果を確認する
ログインの補足（スコープとユーザー＋ロール）

スコープ：

  • expenses:read は default scope のため、追加要求しなくても常に付与
  • expenses:write / expenses:approve は optional scope のため、追加要求したときだけ付与
  • Keycloakのアプリ設定では、経費申請アプリへ expenses:read, expenses:write を、経費承認アプリへ expenses:read, expenses:approve を割り当て
  • アプリに割り当てていないスコープを要求すると、Keycloakがエラー(invalid_scope)で拒否

ログインするユーザー（パスワードはユーザー名と同じ）と、付与されるロール：

ユーザー役職付与されるロール(上位のロールは下位を含む)

admin.sios部長my-director-role + 課長と一般社員のロール(my-manager-role, my-staff-role)
