  • 目的: スコープ(アプリ(RP)に許した操作)と、ロール(ユーザーに与えられた役割)が、APIの許可・拒否にどう関わるかを体験して学ぶ。
  • 題材: 「経費精算」。経費のデータは動作確認用のサンプルで、実際の経費管理はしない。
  • 操作: アプリ(経費申請アプリ / 経費承認アプリ)と、ユーザー(一般社員 staff.sios / 課長 taro.sios / 部長 admin.sios)を切り替えて、APIを呼ぶ。
  • 見るところ: APIが許可(200)されるか、拒否(403)されるか。拒否の理由は、スコープ不足か、ロール不足か。

APIは、スコープとロールの両方を見て実行を許可するか決める。

ログインの補足(スコープとユーザー)
  • expenses:read は default scope のため、追加要求しなくても常に付与
  • expenses:write / expenses:approve は optional scope のため、追加要求したときだけ付与
  • Keycloakのアプリ設定では、経費申請アプリへ expenses:read, expenses:write を、経費承認アプリへ expenses:read, expenses:approve を割り当て
  • アプリに割り当てていないスコープを要求すると、Keycloakがエラー(invalid_scope)で拒否

ログインするユーザー(パスワードはユーザー名と同じ)と、付与されるロール:

ユーザー役職付与されるロール(上位のロールは下位を含む)
staff.sios一般社員my-staff-role
taro.sios課長my-manager-role + 一般社員のロール(my-staff-role)
admin.sios部長my-admin-role + 課長と一般社員のロール(my-manager-role, my-staff-role)
