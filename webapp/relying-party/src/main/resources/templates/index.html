Relying Party (RP)

IdP(Keycloak) → RP(この画面) → RS(Resource Server) の流れを体験する。 このアプリは「経費精算」を題材にしている。申請アプリと承認アプリ、平社員(staff.sios)・課長(taro.sios)・部長(admin.sios)を切り替えて試す。 スコープは「アプリ(RP)に許した操作」、ロールは「ユーザーに与えられた役割」。 APIは、その両方を見て許可するかを決める。

1. ログインする

アプリ(client_id):

要求するoptionalスコープ(アプリに関係なく、自由に選べる):
  • expenses:read は default scope のため、要求しなくても常に付与される。
  • expenses:write / expenses:approve は optional scope のため、要求したときだけ付与される。
  • Keycloakの設定: 申請アプリには write、承認アプリには approve だけを割り当てている。
  • アプリに割り当てていないスコープを要求すると、Keycloakがエラー(invalid_scope)で拒否する。
