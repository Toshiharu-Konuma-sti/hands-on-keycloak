Relying Party (RP)

IdP(Keycloak) → RP(この画面) → RS(Resource Server) の流れを体験する。

  • 目的: スコープ(アプリ(RP)に許した操作)と、ロール(ユーザーに与えられた役割)が、APIの許可・拒否にどう関わるかを体験して学ぶ。
  • 題材: 「経費精算」。経費のデータは動作確認用のサンプルで、実際の経費管理はしない。
  • 操作: アプリ(経費申請アプリ / 経費承認アプリ)と、ユーザー(一般社員 staff.sios / 課長 taro.sios / 部長 admin.sios)を切り替えて、APIを呼ぶ。
  • 見るところ: APIが許可(200)されるか、拒否(403)されるか。拒否の理由は、スコープ不足か、ロール不足か。

APIは、スコープとロールの両方を見て許可するかを決める。

追加で要求するoptionalスコープ:
  • expenses:read は default scope のため、要求しなくても常に付与
  • expenses:write / expenses:approve は optional scope のため、要求したときだけ付与
  • Keycloakのアプリ設定では、expenses:write を経費申請アプリに、expenses:approve を経費承認アプリに割り当て
  • アプリに割り当てていないスコープを要求すると、Keycloakがエラー(invalid_scope)で拒否
